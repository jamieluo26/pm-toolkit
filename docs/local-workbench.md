# 本地工作台：创建任务 → 修订 → 交接

这是在公开 344 文件基线上制作的本地运行候选，尚未发布到 GitHub。它通过本机 Python 调用既有 `pm_task.py`，实际生成原型、PRD 和 Word，并运行对应核对命令。旧的[操作原型](workbench-prototype.md)继续保留。

## 先启动一次

需要 macOS 或具备 `fcntl` 的 Unix、Python 3.10+，以及 `requirements.txt` 中的固定 Word 依赖。当前实际验证环境单独记录；Windows 尚不支持此服务器入口。服务只监听本机 `127.0.0.1`，不供局域网或公网访问。

在工具包根目录运行：

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python pm_workbench.py --workspace ../my-pm-workspace --port 8841
```

在 Chrome 打开 `http://127.0.0.1:8841`。终端保持运行，停止时按 Ctrl+C。端口被占用时换一个端口，并使用终端给出的准确地址。不要把 `127.0.0.1` 改成其他主机名。相同工作目录不能被两个工作台进程同时写入。

工作目录存放自己的项目、草案和运行记录，请放在仓库外并定期完整备份。它不是 GitHub 上传目录。首次创建目录后不要用同步软件、脚本或另一个进程同时修改内部文件。

## 1. 创建任务，生成同一版材料

1. 从空白开始，或显式选择人工合成样例。填写目标用户、问题、定位、价值假设、目标、成功指标、范围、来源、规则和检查条件。
2. 选择集合或表单，编辑字段与样例。字段支持文本、数值、单选和标签。列表还需指定搜索字段；筛选只支持单选或标签。
3. 保存草案，再运行首版生成。工具调用真实 `build` 和 `check`，得到同源 `task.json`、`prototype.html`、`PRD.md`、`handoff.docx`、文档来源、文档核对与待执行检查计划。
4. 打开实际原型预览，并下载需要的文件。预览使用隔离框架；生成的原型数据操作仍限于页面会话，不是业务后台。

缺失的关键文本会明确补为待填写占位并进入 `HOLD`。占位不构成产品决定。错误的类型、范围、选项和引用应修正后重试，不能通过更换标签获得通过。

## 2. 按准确变化处理修订

首版生成后，编辑草案并指定新版本，运行“准备修订”。工具冻结这一次前后材料，生成真实 JSON 路径差异；版本与父版本引用由核心命令处理，无需手填哈希。

为每条反馈填写原意、来源、处理方式和理由，明确选择它对应的实际变化路径，再“保存处理记录并生成修订”。页面中尚未提交的处理记录不算已保存。采纳必须覆盖对应的实际变化；拒绝、待定和冲突各有去向。未决、重复覆盖、遗漏或引用错配会保留 `HOLD`。

准备后又修改草案时，旧准备记录已过期，必须重新准备。旧记录保留；它不会被悄悄绑定到新内容。新修订生成后可以再次修订，不覆盖先前运行目录。

## 3. 实际检查，再生成交接

在生成原型中亲自操作，按当前版本逐条填写观察：条件编号、检查层次、通过/失败/未执行、观察描述、证据引用，失败还要填写缺陷。页面不自动执行这些业务检查，也不认证所填观察的真实性。

失败和后续复验分别追加保存，保留前条引用。新版本的检查恢复为未执行，不能继承旧版通过。交接前核对当前草案是否仍对应选定生成版本。

运行交接会实际执行 `deliver` 和 `deliver-check`，产出交接说明、版本变化、产品手册、观察和文件清单。可以下载单文件或该运行的 ZIP。存在缺口仍可查看、带走材料，但状态保持 `HOLD`。文件一致性通过也不代表真实业务已经验收。

## 保存、恢复与旧草案

保存写入本机工作目录；重新启动时使用相同 `--workspace` 可恢复项目。每次生成、准备、修订与交接使用新运行目录。错误、超时或未完成记录保留供诊断，不覆盖旧版。

页面支持本地草案文件的导入、导出。旧操作原型的 JSON 只转为新草案；其全局观察文字作为未验证备注保留，不转换成逐条通过记录。旧的日期/多行文本字段及集合数值上下限不在当前核心合同内，导入会说明不支持的字段，不能静默丢弃或换型。导入失败保留当前页面材料。

## 当前支持到哪里

- 一个任务选择有限集合或单表单；一个主要需求、一个规则和 1–20 条显式检查。
- 集合支持搜索、交集筛选与侧栏/工具栏；表单支持既有的四状态原型。
- 从明确源材料单向生成。直接改导出的 HTML、PRD 或 Word 不会回写任务。
- 工作台不调用模型，不安装或改动 Skill，不接真实账号、审批或业务数据库。
- 内容保留调用者输入，本身不脱敏。不要在拟公开案例或截图中放入无权分享的材料。
- Word 内容回读由核心核对；实际阅读器中的中文字体、分页、重叠与视觉质量需另行检查。生成器的视觉状态不会因内容一致自动升级。

## 状态怎么读

| 结果 | 含义 |
|---|---|
| 草案已保存 | 输入写入本机项目，尚不等于生成成功 |
| `GENERATED_NOT_ACCEPTED` | 核心生成完成，检查仍待执行 |
| `CONSISTENT` | 给定文件与源材料、关系符合该命令合同 |
| `HOLD` | 材料、反馈、观察或关系仍有未闭合问题 |
| `ERROR` / `INCOMPLETE` | 输入、依赖、进程或写入失败，不能据此交付通过 |
| 已记录观察 | 用户提交了描述与引用，不认证实际执行或真实审批 |

旧 CLI 的[输入合同](task-spec.md)、[完整生命周期](lifecycle.md)与[证据层次](../playbooks/evidence-quality.md)继续适用。当前本地候选的实测范围见[本地验证记录](verification-local-workbench.md)。
