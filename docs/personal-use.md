# 用于自己的产品任务

先填写product-brief.md的定位、痛点、价值与范围，再为讨论材料编号并填写decision-evidence.md。使用requirement-and-interaction.md明确规则与检查，用design-handoff.md记录反馈承接；准备交付时填delivery-and-release.md，版本变化后填retrospective.md。

这些表格需要人工阅读和判断。未知项写“待确认”；它们不会自动被AI或命令补成批准。你可以直接在任意Markdown编辑器中填写；如需Word，按工具包的有限JSON接口提供正文，或使用自己已有的文档流程。

工具包保留你提供的文字，本身不脱敏。它不会上传、自动联网、调用模型、安装Skill、提交Git或发布项目。外部使用这些资料时，另外确认相应权属与分享范围。

init只创建六份空白表和本页，不复制合成案例的决定到你的项目里。
