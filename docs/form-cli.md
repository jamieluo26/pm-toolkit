# 本地表单生成与核对

本模块使用Python3.10+标准库，不安装依赖、不联网、不调用模型。生成的HTML自包含，可本地浏览。实际支持范围见[表单规格合同](form-spec.md)；移动端样式存在不代表移动端已经验收。

## 从示例开始

在工具包根目录运行：

```sh
python3 pm_form.py build --source examples/request-flow/spec.json --output ../my-request
python3 pm_form.py check --source examples/request-flow/spec.json --output ../my-request
```

输出目录必须不存在，父目录必须已存在且不经过软链接。新目录恰好六文件：

- `source.json`：输入完整原始字节；SHA按这些字节计算。
- `prototype.html`：单表单、四状态、会话操作与配置导出。
- `PRD.md`：定位/痛点/价值、字段、状态、给定需求和检查声明。
- `acceptance.md`：待执行计划；不因生成成功而变成已执行。
- `trace.json`：需求与检查的文字关系，状态均为NOT_EXECUTED。
- `manifest.json`：源SHA、生成器闭包及五个制品的指纹；只是可改写的核对材料，不是签名。

源SHA与版本同时出现在原型、PRD、计划及trace。工具不修改输入，也不覆盖已有输出目录。写入中断可能保留 `INCOMPLETE.txt`，应保存失败现场并选新目录，不把残留目录当成功制品。

## 实际操作路径

打开生成的 `prototype.html`：先体验给定值提交，再填写退回补充理由、修改内容、重提，最后完成。已提交和已完成只读。清空必填、越界数值、缺退回理由都应阻止动作并保留当前状态。刷新恢复源值/源初始状态，不会读取服务器或本地持久化数据。

需要换自己的场景时，打开“配置字段与导出规格”。填写新版本及字段配置，生成JSON后可查看/复制或下载。该操作不会修改当前演示的SHA，也不会同步现有PRD。保存为自己的文件，再对这个文件执行build/check，形成新目录；不要手工改生成HTML后假定规格已被回写。

## 漂移与错误

`check` 从当前源规格和当前生成器重新推导六份全部预期字节，检查目录文件集合与每一字节；不信任用户可改写的manifest。手改原型/PRD、伪造匹配manifest、替换同语义但不同原始字节的源文件、出现额外文件或缺文件，均不能通过。

返回0：本条生成/内容一致性命令成立。返回2：输入结构、字段、状态或输出目录合同失败。错误信息不回显调用者正文或敏感路径。CLI不执行页面交互，不证明业务正确、界面已走查、真人审批或生产安全；这些证据另行记录。

仅限调用者明确选择的本地文件。源文件和父目录不通过软链接；硬链接源只读使用，不由工具改写。已有文件/目录/硬链接输出一律不覆盖。全部输入内容都可能保留到制品，使用自己的材料前须自行确认来源与清理内容。
