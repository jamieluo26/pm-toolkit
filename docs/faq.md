# 常见问题

本说明对应 2026-10-27 已公开的 v1.0 本地工作包。该版固定声明范围的公开发布与最终远端验收已闭合；真人反馈和真实业务效果未采集。

## GitHub 上点开 HTML，为什么看到代码？

仓库页面展示源码。使用完整副本，解压后打开本地 `index.html`，再进入案例。公开仓库已包含 v1.0 的已发布内容，下载后核对[版本记录](../CHANGELOG.md)。当前没有在线托管演示；验收中的 Chrome 直接下载 ZIP 客户端拦截仍保留，未记为下载通过。

## 哪些操作需要 Python 或依赖？

浏览预制 HTML、Markdown 和 Word 不需要 Python。独立集合、独立表单需 Python 3.10+ 标准库；完整 `pm_task.py` 路径包含 Word，需要 `requirements.txt` 中的 `python-docx==1.2.0`。在独立虚拟环境安装，再运行 `python3 pm_doctor.py` 检查声明条件。doctor 不自动安装依赖，不证明 Skill 治理或宿主安装成功。

## 怎样准备自己的任务？

从[任务准备页面](../prepare.html)填写有限预设，或用 `pm_task.py init --output ../my-task-input` 创建 task.json。填写定位、用户问题、价值假设、目标、优先级、来源、范围、规则与检查。源合同见 [task-spec](task-spec.md)；未确定内容继续保留。准备页面只导出任务材料，之后还要 build/check。

## 支持什么原型？

集合类支持列表、详情、字面搜索、交集筛选、空态、重置及会话内新增/编辑。表单类支持文本、数值、单选、标签和草稿/已提交/待补充/已完成四状态。它们是有限本地演示，不含账号、后台或多人协作。具体合同见[集合](prototype-spec.md)与[表单](form-spec.md)。

## 表单里的完成是否代表审批？

页面的提交、退回和完成只改变本次会话中的演示状态，没有发送给真实处理人，也不证明此前或当前发生过真人审批。草稿和待补充可编辑，已提交和完成只读；刷新或恢复源样例会重新载入给定状态。

## 输出目录已经存在怎么办？

保留原目录，选择尚不存在的新目录，父目录先存在。生成器拒绝覆盖。中断后有 `INCOMPLETE.txt` 的目录不是成功交付，先保留现场，再选择新目录重试。

## check 成功，是否代表原型和业务验收通过？

check 从源输入重新推导预期产物，证明该范围内的内容一致。浏览器行为、Word 排版、真实业务质量和人的验收分别需要实际观察。自动生成的 acceptance.md 是待执行计划。

## 手改 HTML、PRD 或 Word 后，怎样同步？

确认修改后回到 task.json 或对应规格，再生成新目录。当前是单向生成；手改产物不回灌源文件，check 会识别漂移。它不自由合并任意 HTML/Word。保存手改版本作为评审材料有助于说明意图，但不能用改过的 manifest 隐藏差异。

## 原型里的新增、编辑和状态能保存多久？

只保留在当前页面会话；刷新恢复规格中的样例和状态。长期材料应存入自己的源规格，再生成对应版本。配置页面生成的新 JSON 不会当场改写当前页面的版本或已有 PRD。

## 同版 Word 和 PRD 现在接通了吗？

v1.0 的 `pm_task.py` 通过同任务适配器接通：task.json 内的规格生成原型与 PRD，Word 完整投影这版 PRD 的有序内容，相关标识一致。旧 `pm_toolkit.py` 阅读案例仍用其原合同；不要把旧 Word 与另一个任务的原型混成同版证据。

## HOLD 是失败吗？

结构合法的材料仍可能有待定决定、冲突、陈旧绑定、缺观察或错证据层。命令返回 `3`，保留 HOLD 及原因。结构、依赖或输入/输出合同错误返回 `2`。返回 `0` 也只表示该命令声明范围成立，不等于真人验收。

## 怎样处理失败与复验？

保留 fail 观察及问题描述。相同版本追加复验，supersedes 引用上一条；修改源版本后重新执行并建立新版记录，保留旧版历史。缺记录、未执行、错误层次或旧版本证据继续 HOLD。deliver 仅核对给定记录，不读取或认证引用目标，详见[合同](task-spec.md)。

## 六项 Skills 都已公开、安装并验证了吗？

六项均已纳入 v1.0 的准确公开范围：两项沿用原公开树，四项为本版新增；四项新增树完整治理与六次实际显式调用已通过。使用评测由独立代理执行；真人反馈未采集。目录存在不等于安装或自动发现。只声明有证据的指定 Codex 显式供料方式，不推定其他宿主兼容。输入、输出与人工停点见[当前 Skill 说明](skills-v1.md)。

## CLI 会调用模型、上传材料或改宿主配置吗？

本地生成和核对命令不调用模型或修改宿主。显式使用自己的 AI 助手时，账号、数据处理和费用由该宿主决定。只提供自己有权处理的材料；工具保留内容，本身不脱敏。

## 中文 Word 显示方框怎么办？

先在正常支持中文字体的文档阅读器中查看，并核对其字体替代情况。内容有序回读与实际排版是不同证据；缺字时不能把渲染记为通过。v1.0 不附带字体，具体依赖和来源见[维护说明](maintenance.md)。

## 升级会覆盖我的材料吗？

生成命令使用新目录，固定组件不自动下载更新。保留旧工具、输入、输出和观察，阅读[版本记录](../CHANGELOG.md)，用新工具在新目录重建并核对。原输入合同不自动跨版本迁移，见[维护说明](maintenance.md)。

## v1.0 已完成哪些验收，还保留什么限制？

v1.0 的六工作包、两类有限原型、三个合成场景和六项文字 Skill，以及准确公开资格与最终远端验收，已于 2026-10-27 在固定声明范围内闭合。首次使用评测由独立代理完成，真人反馈和真实业务效果未采集。匿名 Git 新副本的 139 项回归与 7 条固定检查已通过；独立 HTTP ZIP 只核对内容，未单独运行，Unix 模式仅由 Git 证明。Chrome 直接下载 ZIP 的客户端拦截、Word 首轮缺字环境与隔离字体补证继续分别保留。后续独立范围见[路线图](../ROADMAP.md)。
