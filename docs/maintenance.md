# 本地使用与版本维护

每次交接保留准确输入、工具版本、输出、检查记录和未决项。当前目录是 v1.0 本地候选；公开基线仍为 v0.3。本文说明本地运行与升级，不执行安装、部署或发布。

## 运行前

在工具包根目录运行 `python3 pm_doctor.py`，查看 Python、Word 依赖、固定上游摘要和必要资源是否符合本地声明。需要指定另一副本时传 `--root`，详见[支撑工具](support-tools.md)。

完整任务使用独立虚拟环境：

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python pm_doctor.py
```

独立集合/表单模块仅需标准库。Word 内容核对、视觉与正常阅读器字体是不同条件；不分发第三方字体。Windows 命令替换见[生命周期说明](lifecycle.md)，尚未实测的环境不写兼容通过。

## 保留版本

- 任务初版保存 task.json；修订版保留前任务与前规格的绑定，不只修改显示版本号。
- 反馈与处理决定分别保存；状态和原始来源标签保留。
- 每次生成使用新目录。输出中的 task/spec、PRD、Word、trace 与 manifest 保留在一起。
- 实际观察记录对应版本和所需证据层；失败、复验和旧记录继续保留。

`build`、`review`、`deliver` 都是产生新目录的动作；`check`、`review-check`、`deliver-check` 对当前输入重算并检查，不修复已有输出。

## 更新工具包

先保留旧工具副本和正在使用的交接包，再阅读 [CHANGELOG](../CHANGELOG.md)。在新工具副本中运行 doctor，用相同输入生成另一个新目录，检查后再实际走查关键行为与 Word。

当前生成器字节变化可能使旧制品与新版 check 不同；这不意味着应该重写旧证据。旧包用原工具/输入核对，新包留新工具与当前验证。旧合同继续有独立命令和文档，跨合同转换需明确记录。

## 失败与恢复

| 情况 | 下一步 |
|---|---|
| 输出目录已存在 | 保留原包，选新目录；不通过覆盖继续 |
| 依赖或输入 ERROR / 退出2 | 检查 doctor 与准确输入合同；原输入不要混用另一模块格式 |
| 合法 HOLD / 退出3 | 阅读问题，补来源、决定或当前观察；保留冲突，不能只改状态获取通过 |
| INCOMPLETE.txt | 保留中断现场，检查空间/权限等条件，在新目录重试 |
| 手改产物或伪造 manifest 后 check 失败 | 回到明确源输入，保留手改版作为评审材料，再生成新包 |
| 观察是旧版、缺引用或错层 | 对当前版本补做实际检查；不把旧记录只改标识冒充新执行 |
| Word 内容通过但排版有问题 | 用正常阅读器实际检查，保留字体/阅读环境；视觉未通过继续记录 |

完整[生命周期步骤](lifecycle.md)包含每条命令。工具不自动清理原目录、回写原项目或恢复业务系统。

## 固定组件与 Skills

导图与 Word 使用 [UPSTREAM.json](../UPSTREAM.json) 中的固定分发副本。通过本包适配器组织材料，不在组件副本内独立修改；更新组件时明确来源版本、差量与所需回归。

Skill 的完整树治理、实际显式调用和组合回放分别记录。修改说明、模板、夹具、脚本或用例也会改变树身份；旧收据不能自动证明新树。当前支持范围及状态见[Skill 说明](skills-v1.md)。本地工具不安装、自动发现 Skill 或更改全局宿主配置。

## 分享交接包

工具保留输入内容，公开前自行核对源材料、规则、截图、数据、第三方素材和组合识别风险。这里只分享获准准确范围，详细内部来源映射、日志和凭据不进入展示包。新许可证、在线托管或附件另按具体范围决定。

接手人应先读 delivery.md 和未闭合项，再核对原型、PRD、Word、观察和版本。给定证据覆盖不等于来源认证、业务验收或生产发布。
