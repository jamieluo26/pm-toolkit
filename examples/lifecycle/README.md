# 阅读清单完整迭代案例

本目录的讨论、人物意图、书目与处理决定均为人工合成。它用同一任务 reading_lifecycle 的 2.0 → 2.1 证明制作流程，不证明真实用户价值。

1. 阅读 source-notes.md，核对 before.json 的定位、痛点、价值假设、目标和范围。
2. 按 [完整步骤](../../docs/lifecycle.md) 生成前版，操作侧栏筛选，查看同版 PRD 与 Word。
3. 比较 after.json：顶部承载筛选，保留进度/主题、空态、重置和会话维护。
4. review 使用反馈与决定分别给料。采纳顶部载体；拒绝本轮云同步；pending/conflict 文件演示未闭合分支。
5. 生成后版并实际操作；复制观察空白表逐项填写。没有实际执行的项目保持 not_run。
6. deliver 汇总当前版本、给定检查与问题复验，生成交接、变更说明、产品手册和下一轮问题。

## 证据层

生成/一致性、浏览器交互、Word有序内容、Word视觉与目标PM试用分别记录。预制观察若附在本目录，必须标明实际制作环境与来源；不能替代你自己的执行与验收。复制本例状态标签并不会获得真人批准。

## 同源关系

所有 task.json 的需求与 prototype 需求严格对应。spec.json 是本任务内原型的确定性投影；任务与规格SHA记录在 PRD、Word、trace 和manifest。旧版独立阅读演示保留原入口，本案例通过新适配器接通当前交接内容。
