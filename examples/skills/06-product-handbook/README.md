# 零散版本资料，怎样交成一份可维护手册？

版本、规则和决定散落在资料里，接手人难以判断什么已经可用。

本案例输入为新编合成材料；`result.md`是一次明确供料调用的未编辑最终正文；本页的摘要与解读由Codex整理，待维护者核定。它们不是同一层证据，也不代表真实业务已经决定或修改。

## 直接试用

1. 打开[完整调用文本](prompt.md)，复制全部内容到自己的、支持该长度文本的AI助手。
2. 首次可以原样试；用于自己任务时，替换其中材料，保留范围、来源位置和未知项。
3. 对照[本次实际输出](result.md)阅读结果，再自行核对依据与处理取舍。不同宿主可能给出不同表述。

完整调用文本已含准确的[Skill入口](../../../skills/product-asset-handbook/SKILL.md)和下列全部输入，不必先启动服务、填写规格或运行脚本。完整Skill目录仍保留可选模板与验证材料；提示词供料不等于原生安装。

## 给什么，得到什么

- **最低材料：**一个模块的边界、版本声明、设计理由、规则索引、待执行检查与资源。
- **结果形式：**0—8九节产品手册草案，包含证据层次及维护缺口。
- **使用的Skill：**`product-asset-handbook`。

## 合成输入

```text
# 合成输入：个人阅读清单模块资料包

全新合成，仅对以下给定文字形成完整手册草案；不是生产或真实业务验收材料。
- SCOPE-01：模块名“个人阅读清单”；面向个人使用者，目标是找回和整理待阅读条目；包含列表、主题筛选和当前结果导出；不含协作、账号与移动端。
- ARCH-01：给定关系是材料→列表模块→筛选条与结果清单；没有提供源码、路由或生产架构证据。
- VERSION-01：v1草案，主题筛选与导出均在左侧栏。
- DECISION-01：v2设计记录在本合成范围内明确保留两项功能，只将筛选条移至顶部；原因为列表需要更宽内容区。导出放在哪里尚待定。
- VERSION-02：v2本地生成记录声明顶部筛选已生成；此条只是给定生成记录，没有附实际浏览器观察。
- RULE-01：给定规则权威索引为rules-v2.md，摘要：搜索与主题筛选取交集，重置清空全部条件；原规则正文没有提供。手册链接此索引，不复制或改写成新的执行权威。
- CHECK-01：v2待执行条件包括默认3条、筛选结果、恢复全部及导出；没有提供完成记录。
- RELEASE-01：未提供部署、生产运行或真人验收证据。
- IDEA-01：以后可能支持多主题，只是想法，未确定工期或负责人。
- RES-01：给定材料目录是brief-v2.md、rules-v2.md、prototype-v2.html、checks-v2.md；这里仅有文件名和上面的摘要，未提供这些文件全文。
- MAINTAIN-01：建议在版本或规则变更后更新手册；尚未指定维护人。

请按Skill的0到8九节形成中文手册，区分给定设计声明、本地生成声明、未执行检查与未知生产状态。对文件名仅作给定索引，不声称已打开它们；保留导出载体、维护人等缺口，不编造收益或上线结论。
```
