# 讨论完了，究竟哪些已经决定？

两次讨论、两个场景，一句“全部取消”容易覆盖原本有限的决定。

本案例输入为新编合成材料；`result.md`是一次明确供料调用的未编辑最终正文；本页的摘要与解读由Codex整理，待维护者核定。它们不是同一层证据，也不代表真实业务已经决定或修改。

## 直接试用

1. 打开[完整调用文本](prompt.md)，复制全部内容到自己的、支持该长度文本的AI助手。
2. 首次可以原样试；用于自己任务时，替换其中材料，保留范围、来源位置和未知项。
3. 对照[本次实际输出](result.md)阅读结果，再自行核对依据与处理取舍。不同宿主可能给出不同表述。

完整调用文本已含准确的[Skill入口](../../../skills/meeting-decision-evidence/SKILL.md)和下列全部输入，不必先启动服务、填写规格或运行脚本。完整Skill目录仍保留可选模板与验证材料；提示词供料不等于原生安装。

## 给什么，得到什么

- **最低材料：**两次完整可见的合成片段、完整说话人标签、场景与顺序。
- **结果形式：**分场景的决定、演变、冲突和待补材料。
- **使用的Skill：**`meeting-decision-evidence`。

## 合成输入

```text
# 合成输入：两次阅读工具讨论

这是全新合成记录，以下行即全部供料，不对应真人或公司审批。来源分为meeting-01和meeting-02；说话人标签必须完整保留。
上下文维度仅为“个人列表”和“协作画布”，两者是不同场景。时间顺序是meeting-01早于meeting-02，不以时间替代确认依据。

meeting-01 / 片段范围全文：
- S-01 / 讨论者甲：个人列表和协作画布都有人提出导出需求，我们先作为提议讨论。
- S-02 / 讨论者乙：个人列表第一轮是否可以只做复制链接？我倾向于延后导出，还没有定。
- S-03 / 讨论者丙：协作画布需要离线复盘，我建议保留导出。

meeting-02 / 片段范围全文：
- S-04 / 讨论者甲：本次练习范围确认：个人列表第一轮不做导出，复制链接继续保留；这项确认不涉及协作画布。
- S-05 / 讨论者乙：确认个人列表按S-04处理。
- S-06 / 讨论者丙：协作画布导出仍只是提议，格式和目标用户还缺材料。
- S-07 / 讨论者甲：另有人说“所有导出都取消”，但这句话与S-04范围不同，没有给出扩展确认。

请区分确认、倾向、冲突、待材料和背景，写出按上下文区分的决定与演变。不得推定说话人职务，也不要把协作画布写成已取消或已批准。
```
