# 报告写“检查通过”，实际证据够吗？

四条观察看起来对应四个单元，但其中有重复、错版与文案差异。

本案例输入为新编合成材料；`result.md`是一次明确供料调用的未编辑最终正文；本页的摘要与解读由Codex整理，待维护者核定。它们不是同一层证据，也不代表真实业务已经决定或修改。

## 直接试用

1. 打开[完整调用文本](prompt.md)，复制全部内容到自己的、支持该长度文本的AI助手。
2. 首次可以原样试；用于自己任务时，替换其中材料，保留范围、来源位置和未知项。
3. 对照[本次实际输出](result.md)阅读结果，再自行核对依据与处理取舍。不同宿主可能给出不同表述。

完整调用文本已含准确的[Skill入口](../../../skills/supplied-acceptance-evidence-review/SKILL.md)和下列全部输入，不必先启动服务、填写规格或运行脚本。完整Skill目录仍保留可选模板与验证材料；提示词供料不等于原生安装。

## 给什么，得到什么

- **最低材料：**对象/版本/环境范围、四个独立单元、逐字预期与给定观察。

- **使用的Skill：**`supplied-acceptance-evidence-review`。

## 合成输入

```text
# 合成输入：阅读清单v2的给定检查证据

全新合成文本；没有提供实际截图、日志或真实浏览器会话。
对象READING-LIST，版本v2，环境“合成桌面环境A”，时间范围“本次练习”。证据描述不认证真实操作。观察中的“环境A”是前述“合成桌面环境A”的明确简称。
调用者定义的覆盖单元：条件CHK-FILTER × 状态{默认,空结果} × 维度{行为,可见文案}，共4个独立单元。

预期：
- EXPECT-01：CHK-FILTER / 默认 / 行为：默认显示3条。
- EXPECT-02：CHK-FILTER / 默认 / 可见文案：结果计数必须逐字为“显示 3 / 3 条”。
- EXPECT-03：CHK-FILTER / 空结果 / 行为：恢复全部后回到3条。
- EXPECT-04：CHK-FILTER / 空结果 / 可见文案：必须逐字显示“没有匹配条目”。

给定观察：
- OBS-01：READING-LIST v2 / 环境A / 默认 / 行为；记录说打开后3条；没有记录可见文案。
- OBS-02：与OBS-01相同条件、状态、维度，重复记录“打开后3条”。
- OBS-03：READING-LIST v1 / 环境A / 空结果 / 行为；记录说恢复后3条；版本不属于本次v2。
- OBS-04：READING-LIST v2 / 环境A / 空结果 / 可见文案；记录说“暂无记录”，这是给定文字描述，不是已阅读图片。
- SUMMARY-01：记录员写“4条观察对应4个单元，全部通过”。该自填状态不能替代关系和条件核对。

请逐单元审阅覆盖与缺口，区分重复、错版、字面差异；不要把缺证据当已失败的真实操作，也不要宣称你执行了浏览器测试或正式验收。
```
