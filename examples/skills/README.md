# 六个PM问题，六份可对照案例

每个目录都包含：人工合成输入、含完整Skill的调用文本、一次实际AI最终输出、编辑解读及准确摘要绑定。无需启动工具包里的应用即可阅读或复制试用。

- [删侧栏，会不会把功能一起删掉？](01-feedback-intent/README.md)：功能承接、未安置意图与最少补充决定。
- [讨论完了，究竟哪些已经决定？](02-meeting-decisions/README.md)：分场景的决定、演变、冲突和待补材料。
- [改共享组件，有没有漏掉使用它的页面？](03-impact-coverage/README.md)：逐关系处理、漏项、孤立排除和未知范围。
- [需求和验收数量一样，为什么仍然有遗漏？](04-requirement-trace/README.md)：正向路径、反向来源、断链和跨材料冲突。
- [报告写“检查通过”，实际证据够吗？](05-acceptance-evidence/README.md)：逐单元证据覆盖、错位、重复、缺口和最少补证。
- [零散版本资料，怎样交成一份可维护手册？](06-product-handbook/README.md)：0—8九节产品手册草案，包含证据层次及维护缺口。

## 文件怎么读

- `README.md`：先看问题、关键发现和PM下一步；其中解读由Codex整理，尚未宣称真人认可。
- `input.md`：本次完整合成材料，输出行号引用对应它。
- `prompt.md`：完整可复制调用，含准确Skill入口和全部逐行输入。
- `result.md`：未编辑的实际最终正文；不是人工润色后的标准答案。
- `run.json`：输入、完整Skill树和输出摘要及本次宿主信息；不含账号、线程、本地路径或原始日志。

这些是独立的合成案例，不能拼成一个真实项目的会议、审批或生产履历。原始运行日志保存在维护控制区。输入和本轮展示文字由Codex编写、整理；案例结果尚未作为真人体验结论。实际文字调用成功不代替引用核对、人的业务判断或全宿主兼容验证。
