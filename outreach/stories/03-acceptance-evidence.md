# 四条验收记录，为什么不等于全部通过？

> 本文使用合成材料和已有一次实际AI输出，解读由AI协助整理。

验收表里有四项要求，报告也给了四条观察，是否就能写“全部通过”？先别急着看总数。每条观察究竟对应哪个版本、哪种状态，以及行为还是可见文案，才决定它能支持哪项判断。

下面用一个阅读清单练习说明。范围明确为 READING-LIST v2、合成桌面环境 A。给定条件 CHK-FILTER 分为默认、空结果两种状态，每种状态分别检查行为和可见文案，合计四个独立单元。这些划分由练习材料定义，不是要求所有产品都套同一张验收表。

## 表填满了，对应关系仍可能有空缺

[给定预期与观察](https://github.com/jamieluo26/pm-toolkit/blob/46fc45c1dbe01f5352f63a042ecb75267a856c6f/examples/skills/05-acceptance-evidence/input.md#L8-L18)写了以下内容：

| 需要核对的单元 | 预期与已有记录 | 问题在哪里 |
|---|---|---|
| 默认／行为 | EXPECT-01 要求 3 条；OBS-01、OBS-02 都记录打开后 3 条 | 两条记录对应同一个单元，重复不能补另一项 |
| 默认／可见文案 | EXPECT-02 要求逐字为“显示 3 / 3 条” | 已有记录没有给出这段可见文案 |
| 空结果／恢复行为 | EXPECT-03 要求恢复全部后回到 3 条；OBS-03 记录恢复后 3 条 | OBS-03 属于 v1，不能覆盖本次 v2 |
| 空结果／可见文案 | EXPECT-04 要求“没有匹配条目”；OBS-04 记录“暂无记录” | 给定文字存在字面差异，尚未提供真实图片 |

所以，SUMMARY-01 写“四条观察对应四个单元，全部通过”，并没有得到这些对应关系的支持。表面上的数量相等，掩盖了重复、错版、缺项和文字差异。

## 一次实际 AI 草案怎样处理它

本例的[完整调用](https://github.com/jamieluo26/pm-toolkit/blob/46fc45c1dbe01f5352f63a042ecb75267a856c6f/examples/skills/05-acceptance-evidence/prompt.md)明确给出了验收证据审阅 Skill、全部合成文本及行号。已有一次调用的[实际输出](https://github.com/jamieluo26/pm-toolkit/blob/46fc45c1dbe01f5352f63a042ecb75267a856c6f/examples/skills/05-acceptance-evidence/result.md)没有接受自填的“全部通过”，而是逐单元列出：一个单元有一致文字证据，一个单元有字面差异，两个单元缺少适用证据。

这不是“三项真实操作失败”。没有适用证据，表示当前材料还不能支持判断；v1 的恢复记录不能证明 v2 成功，也不能反过来证明 v2 恢复失败。同样，OBS-04 只是文字描述，草案没有看过截图，不能把描述差异直接升级成已经确认的界面缺陷。

## 先补最少证据，再改汇总结论

PM 接下来要补的不是更多相似记录，而是缺少的对应单元：v2 默认状态下的计数原文，v2 空结果状态执行恢复后的条目数，以及同范围的空态直接文案证据。核对实际显示后，再决定是否登记文案缺陷，并更新 SUMMARY-01。

这个方法可以拆成三个动作。先锁定对象、版本、环境和时间，避免把不同范围的记录混用；再按适用状态把行为与文案分别核对，避免一次成功动作替另一种证据背书；最后保留重复和错版记录的原身份，同时列出最少还缺什么。材料不完整时，不把未知强行填成通过或失败。

对读者而言，第一次练习可以很小：先核对这四个单元，再看自己的一份获准材料中，是否把“记录够多”写成了“覆盖完整”。

本文沿用一次已有文字调用，没有执行新浏览器测试、提示词对照或真人效果测量。Skill 给出的是可追溯的审阅草案，不确认真实操作、正式验收或上线批准。案例输入、准确调用、未经编辑的输出及摘要绑定均可复查；本文表格与解释另作编辑解读。
