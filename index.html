02 / THE WORKING METHOD

先组织任务，再选择工具。

六个工作包共享任务、需求、决定与检查关系。输入与判断由人提供，工具生成和核对，实际观察单独记录。

查看六步文字说明
  1. 需求澄清：提供用户、问题、来源与价值假设，形成简报。
  2. 范围与规则：明确纳入、排除、默认与边界，关联需求和检查。
  3. 原型与PRD：从同一任务生成原型、文档和Word，人工核对表达。
  4. 评审修订：保留每条反馈、处理理由和未决项，再生成新版本。
  5. 验证交付：实际操作并记录观察，保留失败、复验与交接限制。
  6. 复盘资产：汇总给定变化、决定状态与下一轮问题。

04 / WHAT IS AVAILABLE

每种能力，都有明确的使用方式。

v1.0 提供两类有限原型与同版任务链。生成、界面操作、Word 排版和人的验收各自需要证据。

  • 材料与决定六个工作包，定位、价值、范围和规则共享一个任务
  • 原型与 PRD集合与表单状态两类，同源文档和待执行检查计划
  • 评审与交付给定反馈、决定、观察与复验关联；未决仍保留问题
  • Word 与资产同版 PRD 有序投影、交接、版本说明与给定资产汇总
  • 文字 Skills六项显式调用已验证，四项新增树完整治理通过；草案需人工核对

为什么在 GitHub 上点开 HTML 会看到代码？

GitHub 显示源码。请下载完整仓库并解压，再打开本地 index.html 体验。当前没有在线托管演示。

修改了规格，怎样让文档与原型一致？

修改规格后生成新目录，再执行 check。直接修改生成文件不会回灌规格；当前不提供任意 HTML/PRD 双向合并。

需要安装模型、账号或云服务吗？

浏览和本地 CLI 不需要模型或账号。使用自己的 AI 助手审阅时，账号、材料处理和费用由你的宿主决定；当前只验证指定 Codex 环境显式供料。
